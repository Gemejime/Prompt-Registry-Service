## Non-Negotiable Invariants

1. **Continuous Doc API Updates**: The [`.ai/doc-api.md`](.ai/doc-api.md) file and the OpenAPI 3.1 specifications (`openapi/openapi.yaml`, `/docs`, `/api/docs`) MUST be kept updated on **every code change or addition**, regardless of how small the modification is.
2. **Secured Logging**: All logging must be structured JSON. Strictly redact raw prompt templates, raw context payloads, PII/PHI, customer secrets, authorization headers, presigned URLs, and database connection credentials before emission. Emit only template IDs, semantic versions, tag pointers, truncated hashes, and latency metrics.
3. **Decoupled Control vs. Data Plane (ADR-001)**: The `rag-prompt-registry-service` exclusively governs administrative metadata, append-only versioning, JSON output schemas, and pointer mutations over low-frequency APIs. String interpolation and dialect compilation run strictly in-process within calling orchestrators via `go-prompt-sdk` (`pkg/promptsdk`) to eliminate network serialization stalls for large context payloads (50 KB parent containers).
4. **Zero-Allocation In-Process Compilation**: String interpolation on the data plane hot path must utilize byte buffer pools (`sync.Pool`) yielding zero heap allocations per render and achieving P99 latency $\le 0.5$ms across 50 KB context blocks.
5. **Instant Cache Coherence via Redis Pub/Sub (ADR-002)**: Semantic pointer mutations (`@production`, `@staging`, `@canary`) are broadcast across Redis Pub/Sub (`channel:prompt:invalidation`) to invalidate distributed in-memory SDK caches within $<100$ms ($<500$ms global propagation SLO).
6. **PgBouncer Simple Protocol Compatibility (ADR-003)**: Relational access to PostgreSQL 16+ via PgBouncer in transaction pooling mode must explicitly configure the Go driver (`jackc/pgx/v5`) with `PreferSimpleProtocol` enabled to prevent prepared statement errors across pooled connections.
7. **Transactional Audit Ledger (ADR-004)**: All administrative template versions and pointer mutations append directly to an immutable `prompt_audit_ledger` table within the same PostgreSQL ACID transaction, deprecating external Debezium/Kafka CDC dependencies.
8. **Tokenizer Budget Safety Guard**: Markup transformers must calculate the structural token overhead of surrounding tags (e.g., Anthropic XML wrapper tags, Meta Llama-3 `<|start_header_id|>...<|end_header_id|>`) using target tokenizer models before injecting context, ensuring downstream inference calls never breach foundation model context windows.
9. **Control Plane Pod Footprint**: Flat memory usage $\le 128$ MiB RSS; CPU requests 100m, limits 500m per pod (handling administrative traffic only).
10. **Code Cleanliness & Quality**: All Go code must pass `gofmt`, strict `golangci-lint` (or `go vet`), and comprehensive unit/integration/benchmark test suites.

## Git Commit Standards

- **Git Commit Frequency**: Commit code as you build. Every working session or phase must contain **at least two git commits**.
- **Conventional Commit Patterns**: All git commit messages must strictly adhere to the following prefixes:
  - `feat:` for new features 
  - `fix:` for bug fixes
  - `refactor:` for code refactoring
  - `docs:` for documentation updates
  - `tests:` for tests addition and modification
  - `chore:` for maintenance tasks and environment setup

## Pre-Commit Verification Rules

Before committing code, submitting changes, or marking a task complete:

1. Run Go formatting: `gofmt -w .`.
2. Run Go vet and linter: `go vet ./...` and `golangci-lint run`.
3. Run test suites & benchmarks: `go test -v -race ./test/unit/...` and `go test -bench=. -benchmem ./pkg/promptsdk/...`.
4. Verify [`.ai/doc-api.md`](.ai/doc-api.md) and OpenAPI 3.1 schemas are updated with all API, schema, or storage modifications.
5. Verify Secured Logging rules: Ensure no raw text, secrets, or PII are logged.
6. Update [`.ai/progress-tracker.md`](.ai/progress-tracker.md).
